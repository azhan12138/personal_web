# Spec: 罗仕展个人主页

状态：Ready for Agent  
产品形态：中文优先的单页静态个人网站  
主要受众：招聘者、潜在合作者、AI 产品与智能体领域的同行  
原型结论：采用 `Editorial Ledger / 编辑档案` 方向，淘汰其余视觉方向

## Problem Statement

罗仕展需要一个可以公开访问的个人主页，用来向招聘者、潜在合作者和
同行介绍自己的教育背景、实践经历以及持续进行中的 AI Native 探索。

现有简历能够罗列学校、课程、竞赛、荣誉和实习，但难以表达这些经历
如何逐步汇聚成当前的身份：一名上海交通大学管理科学与工程硕士生，
同时也是专注 AI Native 的 AI 产品经理、独立开发者与智能体探索者。
单纯的作品集又会放大“作品数量不多”的问题，无法准确呈现仍在成长中
的学生身份、研究兴趣和长期方向。

网站需要同时解决三类张力：

- 求职场景需要教育经历、课程、荣誉、竞赛和实践信息足够清晰、可信、
  易扫描。
- 个人表达需要保留学生气、好奇心和理想主义，不能像一份冰冷的线上
  简历或咨询公司宣传页。
- 公开展示必须保护隐私与商业信息，不能泄露电话、成绩、排名、课程
  分数、业务指标、内部数据、内部系统截图或尚未公开的研究实现。

## Solution

建设一个响应式、中文优先、无需登录的单页个人主页。网站采用已经
验证通过的“编辑档案”视觉方向：象牙白背景、深海军蓝正文、克制的
青绿色与暖金色强调、编辑式网格、中文衬线大标题和简洁无衬线正文。
整体应专业可信，但保留年轻、开放和仍在探索的气质。

页面按以下顺序组织：

1. Hero：身份、核心命题、主要肖像与进入教育/探索内容的行动入口。
2. Education & Academic Foundation：首屏后的第一块内容，以接近简历
   的信息密度展示研究生、本科、课程、荣誉、竞赛和研究关注。
3. Current Focus：解释目前如何把产品、智能体研究与独立开发连接起来。
4. Selected Explorations：展示 Sprout、SoulCompanion 和经过模糊处理的
   AI 视觉识别实验。
5. Journey：用转折点叙事串联本科、研究与竞赛、数据分析实践、AI 产品
   实践、研究生智能体学习和独立开发。
6. Contact：提供公开邮箱与 GitHub，邀请招聘、合作和同行交流。

网站不是传统作品集，也不是简历的逐字搬运。教育板块负责提供求职所需
的可信度，项目与 Journey 负责解释“为什么这些经历最终走向 AI Native”。

## User Stories

1. 作为招聘者，我希望在进入首页后立即看清罗仕展的姓名和职业方向，从而快速判断候选人与岗位是否相关。
2. 作为招聘者，我希望知道罗仕展目前是上海交通大学硕士生，从而正确理解他的职业阶段。
3. 作为招聘者，我希望教育经历位于 Hero 后的第一块，从而不必翻到页面末尾寻找核心学历信息。
4. 作为招聘者，我希望分别看到研究生和本科经历，从而理解他的学习路径和专业变化。
5. 作为招聘者，我希望看到学校、学院、专业、学位和就读时间，从而获得接近简历的信息完整度。
6. 作为招聘者，我希望看到研究生阶段的代表课程，从而判断他在运筹、数据分析、强化学习和智能体方向的知识基础。
7. 作为招聘者，我希望看到本科阶段的代表课程，从而判断他在统计、编程、数据库和管理决策方面的基础。
8. 作为招聘者，我希望看到代表性荣誉，从而快速建立对学习能力和持续投入的信任。
9. 作为招聘者，我希望看到代表性竞赛及奖项层级，从而理解他把模型用于真实问题的经历。
10. 作为招聘者，我希望教育信息易于扫描而不是埋在长段落里，从而能在有限时间内获取重点。
11. 作为招聘者，我希望课程、荣誉和竞赛不带具体成绩、排名或分数，从而既获得必要信息又尊重候选人的隐私选择。
12. 作为招聘者，我希望看到 AI 产品实践的概括，从而理解他不只具备研究兴趣，也接触过真实业务。
13. 作为招聘者，我希望源氏木语的经历只描述职责、问题类型与方法，从而理解能力而不会接触企业内部数据。
14. 作为招聘者，我希望看到 Sprout 的完整产品闭环，从而判断他是否具备从用户洞察到实现落地的独立工作能力。
15. 作为招聘者，我希望能够打开 Sprout 的 GitHub 仓库，从而进一步查看公开代码与项目说明。
16. 作为招聘者，我希望能够打开 SoulCompanion 的 GitHub 仓库，从而了解他对记忆、情绪状态和主动式 Agent 的探索。
17. 作为招聘者，我希望看到经历的转折点而不是所有简历条目，从而快速理解他的成长逻辑。
18. 作为招聘者，我希望通过公开邮箱联系罗仕展，从而发起面试、实习或合作沟通。
19. 作为潜在合作者，我希望首页清楚表达“让一个人的想法借助 AI 走得更远”，从而理解他长期关注的问题。
20. 作为潜在合作者，我希望了解他同时关注产品、智能体和独立开发，从而判断是否存在互补合作空间。
21. 作为潜在合作者，我希望看到进行中的 AI 视觉识别实验只公开方法框架，从而理解方向而不要求披露敏感实现。
22. 作为潜在合作者，我希望项目说明区分已经公开的作品与仍在进行的实验，从而不会误解项目成熟度。
23. 作为潜在合作者，我希望看到 GitHub 个人主页入口，从而继续了解其他公开活动。
24. 作为 AI 产品同行，我希望看到 Agent 如何被用于真实产品和研发流程的关注点，从而判断讨论与交流的共同基础。
25. 作为研究同行，我希望研究生阶段的智能体描述明确标注“仍在进行中”，从而避免把学习与探索误解为已经完成的研究成果。
26. 作为研究同行，我希望看到强化学习、智能体建模与仿真等课程背景，从而理解研究兴趣的来源。
27. 作为同龄学生，我希望页面保留真实的学生身份和成长感，从而不会觉得这是过度包装的商业宣传。
28. 作为同龄学生，我希望文案承认“还没有全部答案”，从而感受到开放、诚恳和持续探索的态度。
29. 作为普通访客，我希望首页的内容顺序自然，从而能从“是谁”逐步理解“学过什么、正在做什么、如何走到这里”。
30. 作为普通访客，我希望主要导航可以跳到教育、经历/探索和联系区域，从而快速到达感兴趣的内容。
31. 作为普通访客，我希望页面中的年份和状态标签清楚，从而区分过去、现在和进行中的内容。
32. 作为普通访客，我希望外部链接明确表现为可点击并在新标签页打开，从而不丢失当前阅读位置。
33. 作为手机访客，我希望在约 390 像素宽的屏幕上完整阅读所有文字，从而无需横向滚动或缩放。
34. 作为桌面访客，我希望页面在约 1440 像素宽的屏幕上保持清晰的编辑式网格，从而获得良好的阅读节奏。
35. 作为低带宽访客，我希望非首屏图片按需加载并经过合理压缩，从而快速看到主要内容。
36. 作为键盘用户，我希望导航和链接拥有清晰的焦点状态，从而不依赖鼠标也能完成浏览。
37. 作为使用屏幕阅读器的访客，我希望页面具有正确的标题层级、地标和图片替代文本，从而理解页面结构与图片含义。
38. 作为偏好减少动态效果的访客，我希望网站尊重系统的 reduced-motion 设置，从而避免不必要的动画。
39. 作为网站所有者，我希望首页不公开手机号码，从而减少隐私风险和骚扰。
40. 作为网站所有者，我希望网站只展示 `18702530496@163.com` 这一公开邮箱，从而保持联系信息一致。
41. 作为网站所有者，我希望旧邮箱不会出现在页面、元数据或测试快照中，从而避免联系渠道混乱。
42. 作为网站所有者，我希望网站不提供原始简历下载，从而避免未经筛选的信息被长期传播。
43. 作为网站所有者，我希望敏感项目不展示真实业务数据、客户信息、内部截图或内部代码，从而满足隐私与安全要求。
44. 作为网站所有者，我希望内容集中维护，从而未来新增项目、课程或经历时不必在多个组件里重复修改。
45. 作为网站所有者，我希望搜索引擎结果准确呈现姓名和 AI Native 方向，从而让他人更容易识别主页用途。
46. 作为网站所有者，我希望社交分享时具有合适的标题、摘要和预览信息，从而避免出现空白或错误描述。
47. 作为维护者，我希望生产实现与探索原型分离，从而不会把临时代码、版本切换器或被淘汰方案发布上线。
48. 作为维护者，我希望生产构建能够在 GitHub Pages 的仓库子路径下运行，从而避免静态资源路径失效。
49. 作为维护者，我希望自动化部署只发布通过构建与验收的提交，从而保证线上版本可用。
50. 作为后续开发智能体，我希望 Spec 明确内容、隐私和验收边界，从而无需重新依赖整段聊天来猜测需求。

## Implementation Decisions

### 产品与内容结构

- 网站采用中文优先的单页结构，不提供语言切换。
- 信息架构固定为：
  `Hero → Education → Current Focus → Selected Explorations → Journey → Contact`。
- Education 是 Hero 后第一块主要内容，不得被 Current Focus、项目或
  Journey 调换到后面。
- Hero 使用以下核心身份表达：
  - 姓名：罗仕展。
  - 身份：专注 AI Native 的 AI 产品经理与独立开发者。
  - 当前阶段：上海交通大学管理科学与工程硕士在读。
  - 核心命题：我想看看，AI 能不能让一个人的想法走得更远。
- 文案以第一人称和进行时为主，传达专业可信、诚恳、仍在学习和持续
  探索，避免把尚未完成的研究描述为既成成果。

### 教育与学术内容

- 上海交通大学条目展示：
  - 2025.09 至 2028.03（预计）。
  - 安泰经济与管理学院，管理科学与工程硕士在读。
  - 代表课程：运筹学（确定性模型）、运筹学（随机性模型）、计算文本
    分析、强化学习、多元统计分析、智能体建模与仿真。
  - 研究关注：开始系统接触 Agent 的决策、协作、建模与模拟机制，并
    持续探索其进入真实产品和研发流程的方式。
- 西南财经大学条目展示：
  - 2021.09 至 2025.06。
  - 管理科学与工程学院，大数据管理与应用学士。
  - 代表课程：机器学习与数据挖掘、统计学、Python 程序设计、数据库
    原理与应用、管理决策模型与方法、数据智能前沿。
  - 代表荣誉：本科生国家奖学金、四川省优秀毕业生、感恩科学家奖学金、

  布局，具有简历式扫描效率，但不使用传统简历表格外观。
- 不展示 GPA、专业排名、单科成绩、CET 分数或荣誉稀缺人数等量化信息。

### 项目与经历内容

- Selected Explorations 固定包含三个条目：
  1. Sprout / 芽：围绕长期目标、日常任务、情绪记录和植物生长反馈的
     移动应用；强调用户研究、PRD、产品设计与 AI 辅助全栈实现的完整
     闭环；链接到公开 GitHub 仓库。
  2. SoulCompanion：探索记忆、情绪状态和主动关怀的桌面 AI 伙伴；
     强调人与主动式 Agent 的关系探索；链接到公开 GitHub 仓库。
  3. 真实世界的 AI 视觉识别实验：标记为进行中；只说明
     Context/Spec/Implement/Evaluate 的研发闭环和真实数据验证，不公开
     数据、内部模型、内部代码、客户或业务系统细节。
- Journey 采用转折点而非完整履历：
  - 2021：从数据与管理出发。
  - 2023：在研究与竞赛中用模型理解真实问题。
  - 2024：从分析走向业务决策。
  - 2025：在源氏木语开始参与 AI 产品落地。
  - 2025 至今：在研究生阶段持续接触智能体研究。
  - 现在：通过个人产品实践 AI Native 的独立开发方式。
- 源氏木语可以实名展示，但只能概括 AI 售后辅助、模拟对练和客服数据
  洞察等方向，不展示准确率、调用量、覆盖率、业务提升、内部字段或系统
  截图。
- 数据分析实习只需支持 Journey 叙事，不公开订单数量、提升幅度、成本
  变化或其他业务指标。

### 视觉与交互

- 采用原型 A 的“Editorial Ledger / 编辑档案”方向，拒绝研究简报式和
  开放笔记式的替代结构。
- 视觉语言为象牙白/纸张色背景、深海军蓝正文、低饱和青绿色强调、少量
  暖金色荣誉强调和细线网格。
- 中文大标题采用有编辑感的衬线字体栈，正文和标签采用清晰的系统无衬线
  字体栈；不依赖必须联网加载的字体。
- 主要肖像使用用户批准的“思考者雕塑前”照片，并提供准确、克制的替代
  文本。
- 项目截图只使用公开 GitHub 仓库中的公开图片。
- 使用克制的滚动显现、链接下划线和轻微位移动效；不使用粒子、3D、
  打字机、视差炫技或自定义光标。
- 所有动效必须尊重 `prefers-reduced-motion`，关闭后不影响内容可见性。
- 导航使用页面锚点；滚动定位需避免内容被顶部导航遮挡。
- 外部 GitHub 链接在新标签页打开并使用安全的 `rel` 属性；邮箱使用
  `mailto:`。
- 所有交互状态必须提供 hover、focus-visible 和 active 的可辨识反馈。

### 技术与架构

- 使用 Vite、React、TypeScript 和原生 CSS 实现。
- 网站为纯静态前端，不依赖运行时后端、数据库或第三方 CMS。
- 生产实现必须重新实现已验证的结构，不直接复制或发布 throwaway
  prototype 代码。
- 公开内容应集中为类型明确的内容数据，由展示组件消费，以便统一维护、
  隐私审查和测试。
- 页面按语义区域组织，至少包含 header/nav/main/section/footer 等正确
  地标与连续的标题层级。
- 首屏肖像可以优先加载；非首屏图片延迟加载并提供明确尺寸，减少布局
  偏移。
- 图片应在不明显损害质量的前提下压缩，避免把原始超大素材直接发布。
- 配置适用于 GitHub Pages 仓库子路径的资源基址。
- 通过 GitHub Actions 构建并部署 GitHub Pages；只有通过检查的提交才
  进入部署步骤。
- 元数据至少包含中文页面标题、描述、规范链接、Open Graph 标题与描述。
  若没有单独制作社交分享图，可暂时使用经过裁切与压缩的主肖像。

### Release acceptance

- 生产页面必须按照已确认顺序完整呈现六个区域。
- 教育经历必须是 Hero 后第一块主要内容。
- 所有确认的公开链接必须可访问且指向正确目标。
- 页面源码、可见文本、元数据和构建产物均不得包含被禁止的隐私或业务
  指标。
- 桌面和手机验收视口均不得出现页面级横向滚动、文字裁切、内容重叠或
  无法操作的链接。
- 正式页面不得包含 A/B/C 切换器、THROWAWAY PROTOTYPE 标签或被淘汰
  的 B/C 结构。

## Testing Decisions

- 主要行为测试只使用一个最高层验收缝：在真实浏览器中打开生产构建后
  的完整单页网站，从访问者视角验证外部行为。
- 浏览器验收使用 Playwright 或等价工具运行，不测试 React 内部状态、
  私有组件结构、具体 CSS 类名或实现细节。
- 浏览器验收至少覆盖：
  - 1440×1000 桌面视口。
  - 390×844 手机视口。
  - 页面区域顺序，特别是 Education 紧随 Hero。
  - 两段教育经历、代表课程、荣誉和竞赛的可见性。
  - 三个探索项目及其状态、公开仓库链接。
  - 邮箱、GitHub 主页、页内导航和外部链接行为。
  - 页面 `scrollWidth` 不超过 `clientWidth`，即不存在页面级横向溢出。
  - 键盘 Tab 导航、可见焦点与合理的标题/地标结构。
  - reduced-motion 环境下内容仍完整可见且无强制动画。
  - 页面标题、描述与基本 Open Graph 元数据。
- 隐私使用负向外部行为断言：页面可见文本、HTML 与生成产物中不得出现
  电话号码、旧邮箱、GPA、专业排名、单科分数和已明确禁止的业务指标。
- 类型检查与生产构建是发布门禁，但不作为第二套行为测试缝。
- 测试应断言用户能够看到或完成的结果，不做像素级全页快照，也不依赖
  动画时间、DOM 深层结构或具体样式实现。
- 视觉 QA 使用桌面与移动端截图人工检查，重点检查层级、换行、裁切、
  图片构图和整体气质；截图用于评审，不作为易碎的像素级回归基线。
- 当前仓库没有既有生产测试可复用。原型阶段的桌面/移动截图与浏览器
  溢出检查是设计依据，但生产测试需要在正式实现中重新建立。

## Out of Scope

- 英文版或中英文语言切换。
- 博客、文章系统、RSS 或持续内容发布平台。
- CMS、后台管理、账号系统、数据库或服务端 API。
- 站内联系表单、验证码、邮件发送服务或预约系统。
- 公开电话号码、原始简历下载或完整简历逐条复制。
- 公开 GPA、排名、课程分数、CET 分数或具体业务提升指标。
- 公开尚未完成的智能体研究成果、论文结论或未经批准的数据。
- 公开 AI 视觉识别项目的内部数据、模型、代码、客户或业务系统。
- 独立项目详情路由；首版项目内容全部位于单页主页。
- A/B/C 原型切换器以及被淘汰的 B、C 视觉结构。
- 复杂 3D、粒子、视差、打字机效果、自定义光标或声音。
- 用户行为追踪、广告、第三方营销分析或 Cookie 画像。
- 暗色模式。
- 自定义域名；首版使用 GitHub Pages 默认地址。
- 对简历中所有项目、活动和奖项的完整归档。

## Further Notes

- 原型分支 `prototype/homepage-directions` 是视觉探索的第一手资料；选定
  结论位于提交 `e37f9c0`。正式实现应参考其结构和气质，但不能直接把
  原型代码合并到生产主线。
- Spec 是生产开发的权威上下文。后续对需求、隐私、内容顺序或产品取舍
  的修改，应先更新 Spec 或在关联 Issue 中记录决定，再修改实现。
- 公开文案应避免“专家”“成熟体系”“已经完成研究”等超出当前事实的
  表述。优先使用“开始系统接触”“持续探索”“正在学习与深耕”等准确
  措辞。
- 如果后续增加新项目，应先确认其公开状态和隐私边界，再进入页面内容
  数据。
- GitHub Issue 发布后，应在 Issue 中保留原型分支与本 Spec 的上下文
  指针，并应用 `ready-for-agent` 标签。
